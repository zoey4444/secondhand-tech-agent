# 二手数码交易助手 MVP

## 运行

1. 在项目文件夹中打开 PowerShell。
2. 激活你已有的虚拟环境，或先创建并激活 `.venv`。
3. 安装依赖：

   ```powershell
   python -m pip install -r requirements.txt
   ```

4. 复制 `.env.example` 并命名为 `.env`，在 `.env` 中填写自己的 DeepSeek API Key。不要把密钥发给别人或提交到公开仓库。
5. 启动网页：

   ```powershell
   streamlit run app.py
   ```

## 当前能力

用户按三个卡通步骤填写交易平台、产品类别与型号、价格和商品信息。右侧的商品形象会随输入逐步成形。点击“生成商品，进入投掷场景”后，用户可拖动商品到购物车，或点击“一键投掷”。如果信息不足，商品停在车外；发现型号、价格冲突或其他待核实风险时，商品被弹回；规则无冲突且模型明确表示当前材料未见明显异常时，商品进入购物车。反馈按六块拼图展示，点击可展开详情；“建议向卖家核实”拼图提供一键复制按钮。

卖家回复后，把新内容贴进页面底部的“卖家的新回复”，点击“根据卖家回复重新分析”。页面会把原商品、之前的回复和上一轮疑点一起分析，新增“回复后的变化”拼图，并显示购物车判断是否变化。可以继续第三轮追问。卖家自述不会自动变成已核实的事实。浏览器会话刷新或服务重启可能清除历史；重要材料请自行保存。修改原商品价格、型号或描述后，点击上方“生成商品”重新开始核验。

首次填写卖家沟通内容及后续卖家回复时，也可以上传 1–3 张 PNG、JPG 或 WebP 聊天截图。点击“识别截图中的对话”，DeepSeek 会转写可见文字；使用者须在可编辑的识别结果中检查错字和说话人，再点击商品核验或重新分析。图片在上传前应遮盖头像、姓名、电话、地址、账号及完整序列号。识别请求会将处理后的截图发送给 DeepSeek；应用仅把核对后的文字传入后续风险分析。

页面使用 `#caebed`、`#cce7d9`、`#63bad9` 和 `#B5dae9` 四种主题色。更新代码后如网页没有自动刷新，在运行窗口按 `Ctrl+C`，再执行 `streamlit run app.py`；无需重新安装依赖。

LangGraph 先运行 Python 规则扫描，再根据证据是否完整分流到不同分析节点；随后结合平台提示和品类验货清单调用 DeepSeek。原型适用于多个交易平台，因为它分析用户提供的内容，不依赖某个平台接口。进车表示基于当前材料可考虑购买，购买前仍需验货与核对凭证。

## 首轮验证

型号快捷选项只是常见系列入口，用户可选择手动填写准确型号。先准备 20 条脱敏或自行编写并标记为模拟的案例，覆盖信息完整、关键字段缺失、描述矛盾、异常付款要求、平台差异和品类差异等情况。逐条检查：是否引用了输入证据、是否编造结论、问题是否可执行、平台提示和检查清单是否匹配。记录错误和改进，不要只展示一条成功案例。

## 让其他人通过网址使用

详见 [部署与分享指南](DEPLOY.md)。上传代码前检查：**不要上传 `.env`，不要把 API Key 写进代码、截图或仓库**。公开分享时，访客的每次分析都会调用你配置的 DeepSeek API；请在服务商后台关注用量。
